# Neon Hollow: Dustline

A mobile-first comic-wasteland action roguelite inspired by the tactile weapon loop of arcade survival shooters. The game runs directly in the browser and is designed for portrait play on iPhone.

## Vertical slice

- Phaser 3 + TypeScript + Vite architecture
- Touch joystick, keyboard movement, hold-to-fire and optional one-thumb AUTO mode
- R-12 rifle with magazine, reload, recoil, spread, and critical hits
- Raider, ranged spitter, brute elite, and a boss encounter
- Ninety-second enemy rush; defeat the Foreman to complete the contract
- Three starting rifle modules (damage, extended magazine, critical chance)
- Scrap XP and three-choice field modifications
- Original procedural inked sprites, four-frame hero walk, muzzle flash, halftone UI, damage numbers, and camera shake
- Physics and weapon timers freeze during pause, upgrade selection, and results
- Installable PWA and automatic GitHub Pages deployment

## PlayCanvas 3D prototype (Phase 1)

The game is migrating from Phaser 2D to a PlayCanvas 3D presentation. The Phaser game above remains the gameplay reference and is unchanged; the 3D vertical slice lives separately:

- Page: `playcanvas.html` → `src/playcanvas/` (the Phaser game stays at `index.html` → `src/main.ts`)
- Run: `npm run dev:3d` (or `npm run dev` and open `/mobile-roguelite/playcanvas.html`)
- Controls: WASD / arrows to run, hold Shift to walk; on touch, drag anywhere (a light push walks). The **tune** button shows live sliders for camera pitch, distance, height, FOV, screen offset, follow smoothing, look-ahead and character scale; values persist per browser and **copy values** puts them on the clipboard. The gameplay camera (52° pitch, 15.2 m, 42° FOV; the baseline framing) shows ~2.2x the ground of the earlier close view (about 12 x 18 m on a portrait phone) with the hero about 13% of the screen height, so hordes are visible coming from every side.
- Characters (switch in the **tune** panel or with `?model=survivor|vanguard|brawler2k|brawler4k|orc`): Survivor (V3, default; the "Zombie Apocalypse Survivor" Mixamo character built by `scripts/build-survivor.mjs`: its own three Mixamo idles plus all 17 Vanguard clips retargeted onto it by matching bone directions, torso and head by rest pose; relaxed finger curl baked in, texture 2048 WebP, 2.1 MB), Ironclad Vanguard ( mesh, rig and all 17 animations untouched, textures resized to max 2048 WebP, 22.6 MB -> 5.4 MB; real `Idle_10` idle plus unused weapon clips for later), Wasteland Brawler with textures resized to 2048² (default; mesh, rig, animations and materials untouched), the original 4096² Wasteland Brawler, and the Iron Shoulder Orc. Files live in `public/models/`; the original brawler GLB is also attached to the `model` GitHub release.
- Tuning: `src/playcanvas/config.ts` (camera, movement, animation thresholds, lighting)

Modules: `Game.ts` (bootstrap), `player/PlayerController.ts`, `player/PlayerAnimationController.ts`, `player/CharacterLoader.ts`, `camera/CameraController.ts`, `input/*` (move-input sources; a mobile joystick plugs in as another `MoveInputSource`), `world/Environment.ts` (lights, IBL, fog), `world/Arena.ts` (placeholder props and procedural fallback ground), `world/Ground.ts` ("Damaged Road" PBR ground from `public/textures/road_damaged/`, plus a "Rocky Terrain" overlay from `public/textures/rocky_terrain/` covering the far third of the arena with a soft, irregular border; normal and roughness maps converted from the supplied EXRs), `world/ContactShadow.ts`, `ui/DebugPanel.ts`.

Level 1, "Dustline Outpost" (`world/level/OutpostLevel.ts`): a 48 x 80 m abandoned industrial compound fortified by survivors, built from the Atomic Realm packs. South to north: **entry** (road chicane, spike barricades, a taller fortified wall with a half-open plank gate, floodlit gate towers, an abandoned car), **main yard** (open combat space with a survivor camp, barricade line, stripped car and junk pile), **industrial depot** in the east (concrete yard, two-storey warehouse with a partly collapsed roof, stacked containers, fuel depot, storage corner), **infected ruins** in the west (scorched soil, roofless ruined house, flipped car, stake field, beached boat) and a **boss arena** in the north (open ~20 m ring, cover at the edges, floodlights, a beached ship hull as landmark). A modular road leads from the gate to a T junction; its arms dead-end in the ruins and exit (barricaded) through the east wall. The file holds layout data plus three helpers: `wallRun` (2 m wall modules along a line, with pattern, gaps, stacked rows and posts), `cluster` (composed prop groups rotated as one) and `place`. **DEV MAP VIEW** (tune panel "map view", the M key, or `?map=1`) frames the whole level from above; the gameplay camera is unchanged.

Environment kit (`world/props/ModelKit.ts`, model rules in `world/props/OutpostKit.ts`): `scripts/build-outpost-kit.mjs` merges 72 models into `public/models/outpost/outpost-kit.glb` (~2.8 MB, ~74k triangles): Atomic Realm Post-Apocalyptic Starter Pack, Gas Station, Interiors, Into The Wild, Ocean and Modular Roads (primary look), CitySurvivalLite and 3dassets.dev CC0 props (secondary). Every material except the road tiles is baked into vertex colours on one shared "palette" material (the Atomic Realm atlases are flat colours and linear gradients, which per-vertex sampling reproduces), so the whole kit is 4 materials and batches into a few draw calls per 12 m cell; heavy repeated meshes are simplified. `ModelKit` clones models, puts shadow casters and shadowless clutter in separate batch groups, and declares colliders from each model's footprint (box or circle, scaled with the instance; walk-over clutter has none). The older primitive kit (`world/kit/`) is kept but no longer used by the level. Ground (`world/Ground.ts`): stylized surfaces painted procedurally at load (sand, packed dirt, concrete slabs, scorched ash; no downloads, no normal maps), an opaque base, opaque pads and soft-edged patches placed by the level's ground spec.

Collision (`world/collision/`): kit prefabs declare 2D footprints with `kit.solid(parent, { kind: "box" | "circle", ... }, x, z)`, which tags the entity `solid`; `CollisionWorld.addStaticFrom(root)` registers every tagged entity (oriented boxes and circles on the X/Z plane, uniform-grid broadphase). The player is a circle (`PLAYER.colliderRadius` x character scale) that moves with sub-stepped move-and-slide, so diagonal moves into walls keep the along-wall motion. Pallets and rubble piles are walk-over. `DEBUG.DEBUG_COLLIDERS`, `?colliders=1` or the tune panel's "colliders" button shows the footprints.

Weapons (`player/WeaponHolder.ts`, `WEAPONS` in config): 17 hand-held weapons merged by `scripts/build-weapons.mjs` into `public/models/weapons/weapons.glb` (~2.9 MB): six from "assetpack-free" (assault rifle, shotgun, sniper rifle, pistol, knife, frag grenade; textures 2048 -> 512 WebP), ten "Flat Guns East" guns (flat colours baked into vertex colours on one material, one draw call each) and a low poly axe by Yevhen Ishchenko (FBX converted with `scripts/fbx-to-glb.mjs`, 512 PBR maps). The chosen weapon (tune panel "Weapon", or `?weapon=<id|none>`) is parented to the hero's `mixamorig:RightHand` bone with a per-weapon grip (position, rotation, roll, optional scale). Two-handed weapons are held through grip frames (`GripFrame` in config: a point, the handle axis from little finger to index finger, and the direction toward the palm). Each weapon may define `grips.right` (pistol grip) and `grips.left` (handguard) with a handle radius; each character defines `hands.right` / `hands.left`, its palm frames in its own hand-bone space (the Survivor's measured on its mesh, the Vanguard's derived from its verified hold). Hierarchy: RightHand bone → `WeaponSocket` (right palm frame) → weapon (its right grip, moved out to the handle surface, sits on the socket) → `RightHandGrip` / `LeftHandGrip` markers. Each frame after the animation (`player/WeaponHands.ts`): the spine aim twist; the right palm stays where the animation put it while the hand turns into a pistol-grip hold so the weapon points along the animated aim and stays upright, with right-arm IK (`player/ArmIK.ts`) moving wrist and elbow behind the grip; left-arm IK puts the left palm frame on `LeftHandGrip` (position and wrist orientation, with a small roll around the handguard to follow the animated wrist); then `player/FingerGrip.ts` bends each finger joint until it touches the handle cylinder (a trigger finger stops short on rigs with separate fingers). Arm IK keeps the animated elbow plane but may swivel the elbow to straighten the wrist, can swing the collarbone for reach, and splits hand roll between forearm and wrist. Weapon classes (`WEAPON_CLASSES` in config) set how each kind of weapon is carried; each weapon in `WEAPONS` sets its `class` and exact grips (and `stock`), measured on its model. **pistol**: compact two-handed ready stance with the elbows held out and a little down (class `elbows`: arm IK swings each elbow toward that direction, so the shoulder → upper arm → elbow → forearm chain stays readable from the top-down camera instead of tucking under the chest), grip in front of the upper chest (anchored to `mixamorig:Spine2`, bobbing with it), aiming along the facing; upper body = the character's idle (`pose: "@idle"`), legs keep Idle / Walk / Run. **rifle**: the `Run_and_Shoot` upper-body clip aims, the right palm stays where the clip puts it, spine aim twist on. **shotgun**: stock in the right shoulder pocket (anchored to the right shoulder joint), level and aiming along the facing when standing, dropping into a lowered carry across the body at a run; the left hand far forward on the pump / fore-end. **axe** (one-handed melee, also knife / grenade): no firearm pose or IK; locomotion and the attack clips move the weapon (the axe keeps its legacy hand transform). **heavy**: hip-carried two-handed profile, ready for a minigun. Full-body action clips (attacks) fade the upper-body layer, and with it every IK correction, so procedural hands never fight an attack. Weapons without `grips` (sniper, East rifles and SMGs, knife, grenade, axe) keep the legacy hand transform and their class pose. The tune panel's **weapon** button opens a weapon tuner for the held weapon: sliders offset its right grip / socket (position, rotation), scale, left grip and stock (or the legacy transform), live, with the grip frames drawn (white line = weapon forward axis, magenta = stock); **copy weapon** puts the resulting `WEAPONS` entry on the clipboard. `node scripts/weapon-pose-sheet.mjs [url] [out dir] [weapons]` captures each weapon at four facings standing and running, its attacks mid-swing and hand close-ups (plain and with grip frames) into an HTML contact sheet (dev only; needs Playwright). The Survivor's rig has only one finger joint per hand that moves the mesh (`HandIndex1` carries all four fingers; `Index2`–`4` drive no vertices; no thumb bones), so its fingers close as one block. The Vanguard has sculpted fists and no finger bones. Weapons without `grips` keep the legacy per-weapon transform (and `handRollDeg` for rigs whose hands are rolled differently). The tune panel's **grips** button (or `?grips=1`) draws the RightHand, WeaponSocket, LeftHand and LeftHandGrip frames (RGB = XYZ) and the left-wrist IK target. Because the aiming clip is authored with the torso turned, an aim correction (`player/AimTwist.ts`, `AIM` in config) runs before the IK: it twists the three spine bones (up to 30°, smoothed) so the held gun points where the hero faces (within a few degrees while walking and running). Guns switch on an upper-body animation layer (masked from `mixamorig:Spine` up) playing the aiming clip `Run_and_Shoot`, so the arms hold the gun forward while the legs keep idling, walking or running. Melee weapons have an attack: Space or the on-screen ATTACK button plays `Axe_Spin_Attack` (axe) or `Attack` (knife) once on a full-body action layer.

Roguelite run (`src/playcanvas/gameplay/`, all tuning in `gameplay/config.ts`): the outpost is one arena for three levels. **Level 1** (Walkers, then the **Brute**), **Level 2** (+ Runners, then the **Charger**: red lane telegraph, charge, overshoot and a vulnerable recovery), **Level 3** (+ Throwers lobbing slow toxic blobs with landing rings, then the **Mutant Tank**: melee, lobbed projectiles, telegraphed ground slam). After each boss: choose 1 of 3 upgrades, then a shop (heal, max HP, armor, damage, fire rate, Shotgun, Assault Rifle); the run ends after the Tank (~12-13 min). The hero starts with the pistol in the open yard. Controls stay one-thumb: move with the joystick, the gun auto-aims (preferring enemies ahead of where you steer, in line of sight) and auto-fires; the hero turns to the target while the legs keep running. Systems: `SpawnDirector` (data-driven rate / group size / cap / type mix ramps, groups from one direction on a ring outside the camera view, only on navigable cells connected to the player; the boss arrives while regular spawns continue), `EnemyManager` (behaviour and looks are separate: an `EnemyDef` holds the AI and stats and lists its `ENEMY_VISUALS`, each a GLB plus its clip names, scale and foot-matched walk speed; every spawn picks one variant, so the Walker wears four different zombie models on one behaviour. Pools per look, built on demand; hit flash and a short hit flinch; random death clip; flow-field chase from `NavField`, separation, melee wind-ups, boss specials; no sun shadows, a shared soft blob shadow each). Walkers are the Low-Poly Zombie pack characters built by `scripts/build-zombies.mjs`: Vanguard walk / death clips retargeted onto their Unity rig, with a hunched, head-tilted, arms-forward zombie posture layered on top, and a procedural two-arm claw attack and hit flinch (no player or weapon poses); ~1.5k triangles and ~430 KB each. Four colour skins (sick green, dark green, bruised purple, decayed brown) are recoloured copies of the pack's swatch palette (~38 KB WebP each in `public/models/zombies/skins/`, shared by every zombie model): each spawn picks a model and a skin, so a horde never looks like clones while staying one coherent infected palette. Runners are the pack's lean sport bodies (narrowed, sprinting with a retargeted run under a deep lean); Throwers are the lab-coat zombie in a toxic yellow-green skin, a little swollen, with an overhand throw clip timed to the blob release; the level-1 **Brute** boss is a big (~1.4x the hero), bulked-out zombie in a dark bruised skin with a slow overhead smash timed to its wind-up. Each look may set a width / depth `bulk`; looks sharing a model file download it once. The Charger and Mutant Tank bosses still use the Vanguard rig, `PlayerGun` (hitscan bullets with spread, pellets, penetration, crits, magazine / reload; walls stop bullets), `Pickups` (cash: a stylised green banknote bundle with a paper band, one merged vertex-coloured mesh per drop, popping in, bobbing and spinning, shrinking into the hero when collected; red-cross health; rare upgrade badges; small magnet), `Hazards` (telegraph rings / lanes, lobbed projectiles), `Effects` (pooled muzzle flash, tracers, sparks), `Upgrades` (effects on `PlayerStats`, stackable; each `UPGRADES` entry is data: name, stat, value, icon, category, rarity, stack limit, so the HUD toast, reward cards and world badge all draw from it; icons are small SVG path glyphs in `ui/UpgradeIcons.ts`, drawn inline in the HUD and onto canvas textures for the world). An upgrade pickup is a rare glowing round badge with its icon (category colour: amber weapon, blue player, purple special), floating, bobbing and swaying; collecting it pops the icon above the action (0.5 → 1.15 → 1 with a glow ring), shows a compact name / stat card (under half the screen width) and a ring pulse around the hero, then fades after ~1.6 s without pausing play, `Hud` (GTA III style top-right money (`20$`, no padding) in outlined green with a sweeping shine and a pop when it rises, and health as a plain pink number with a heart that bumps on hits and blinks below 25%; level timer, weapon / ammo, boss bar, damage numbers, upgrade and shop cards). Debug: the gear button shows the old stats / tune panel (or `?debug=1`), `?level=2` starts at a level, `?levelTime=0.2` shortens the waves, `?weapon=shotgun` starts with a weapon, `?sandbox=1` is the old movement sandbox without enemies.

Performance notes: the scene is fill-rate bound (full-screen ground shading). Fill/rim lights only affect the hero (light mask), the ground skips image-based lighting, only a thin border strip of the rock layer is transparent, shadows are PCF3 at 1024, and a dynamic-resolution governor (`perf/ResolutionGovernor.ts`, `RENDER` in config) lowers the pixel ratio when fps drops. The stats line shows resolution, draw calls and triangles.

Texture library in `public/textures/` (1K PBR sets from the supplied `.blend.zip` files; colour JPG as supplied, EXR normal/roughness/metalness converted to 8-bit JPG, displacement not used): `road_damaged`, `rocky_terrain`, `rusty_metal_grid` (kit painted panels), plus `rusty_metal_04` (with metalness map), `worn_planks`, `broken_brick_wall` and `cracked_concrete` (not placed yet).

Known gaps: the GLBs have no real idle; `player/BreathingIdle.ts` generates a looping breathing idle from the static `restpose` A-pose (relaxed arms, chest and shoulder lift; tune in `IDLE` in `config.ts`) until a hand-made Idle clip exists, the 20 MB GLB and its 4096² metallic-roughness texture are not optimized yet.

## Controls

- **Mobile:** left joystick to move; hold **FIRE** for assisted aiming, drag it to aim manually, tap **RELOAD**
- **One-thumb:** toggle **AUTO** to shoot automatically while moving
- **Desktop:** WASD or arrow keys, Space to fire, R to reload
- **Pause:** top-right button, P, or Escape

## Run locally

```bash
npm install
npm run dev
```

## Build

```bash
npm run build
```

Node 22.18+ is required. `npm test` runs 17 simulation and scene-lifecycle regression tests. The scene tests use physics/UI doubles; they do not replace real-browser checks or device performance testing.

GitHub Actions runs the tests, checks TypeScript, builds Vite, and publishes only `dist/`. Fonts are self-hosted. The service worker precaches versioned build assets and limits cache cleanup to Neon Hollow caches. Offline play requires one complete online load.

## Modules

- `src/game/GameScene.ts`: combat, enemy behavior and scene lifecycle
- `src/game/Weapon.ts`: independently tested weapon simulation
- `src/game/TextureFactory.ts`, `World.ts`: original procedural art
- `src/game/config.ts`, `types.ts`, `math.ts`: tuning and shared rules
- `src/main.ts`, `styles.css`: DOM HUD, touch controls and menus
- `scripts/build-sw.mjs`: cache manifest generated from the production build

Version 0.1's Canvas implementation remains recoverable in Git history. Full rooms, multiple weapons, loot inventories, persistent progression, sound, and a production sprite atlas are not included in this vertical slice.

The current art is an original code-drawn comic wasteland treatment used to validate feel and performance. The next production pass will replace it with a cohesive animated sprite atlas while keeping the same gameplay systems.
